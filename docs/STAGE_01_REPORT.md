# تقرير المرحلة الأولى — دواء وحياة

تاريخ العمل: 22 أكتوبر 2026، بتوقيت اليمن. الحالة: تنفيذ قابل للمراجعة، **المرحلة لم تُغلق**.

## المنفذ

- تطبيق Flutter Android واحد: API 26، عربية/إنجليزية، RTL/LTR، ثيم فاتح/داكن، بحث ومفضلة وإعدادات وسجل قراءة محلي.
- 12 مقدمة تعليمية أصلية ثنائية اللغة في Drift/SQLite، مع مصادر ورخص، دون جرعات أو اعتماد سريري وهمي.
- تبويبات رئيسية وجسم الإنسان والأمراض والأدوية ومكتبتي، وتفاصيل وتنزيلات ومعاينة سحابية وإعدادات ومصادر.
- محرك حزم واحد: تأكيد اختياري، تقدم حقيقي، إيقاف/إلغاء، استئناف على مستوى الملف، مساحة خالية، SHA-256، تثبيت معاملاتي وحماية الإصدار السابق.
- عارض Three.js محلي داخل مساحة WebView مخصصة للمجسم فقط. النموذج الأصلي الهندسي ليس تشريحًا طبيًا.
- مشروع Neon مستقل `plain-term-00662915` في `aws-eu-central-1`، فرع تطوير `br-still-mode-balcyppo`.
- ثلاثة ترحيلات، 19 جدولًا، 24 صف ترجمة، أربع حاويات خاصة، Function حقيقية وواجهات قراءة محمية ببوابات النشر والترخيص.

## الإثبات

11 اختبار Flutter و6 اختبارات API نجحت. التحليل البرمجي دون ملاحظات.
اختبارات فعلية على Neon أثبتت عدم كشف المسودات والمحتوى غير المرخص، ورفض
وصول دور القراءة للجداول الخاصة أو الكتابة. تنزيل الحزمة `circulation-demo` v1
من Neon نجح: 2225 بايت وثلاث بصمات مطابقة. تفاصيلها في LIVE_SMOKE_EVIDENCE.json.
قراءة الملفات على المضيف بعد التنزيل نجحت؛ لا تمثل إثباتًا لوضع الطيران على Android.

## شروط القبول المفتوحة

- التحقق من اكتمال نتائج CI والبناء والجهاز قبل الدمج.
- تجميع Android ARM64 داخليًا؛ لا توجد Android SDK/محاكيات في المضيف المحلي.
- تشغيل API 26 وإصدار أحدث، وقياس 3D، وإثبات النص والصورة والمجسم عند فصل الشبكة فعليًا.
- سيناريوهات انقطاع الشبكة/قتل التطبيق/امتلاء التخزين على الجهاز، ومراجعة قابلية الوصول بصريًا.
- إدارة تبعيات الحزم وتحديثاتها الكبيرة وتنظيف الأيتام بعد الانقطاع قبل دعم الحزم المعقدة.
- مراجعة بشرية للمحتوى قبل اعتباره علميًا/سريريًا معتمدًا، وفحص أمني أوسع لتبعيات Dart.
- نشر مخطط وخدمات فرع Neon الرئيسي بعد اجتياز بوابات المراجعة؛ الحالي في فرع التطوير فقط.

لم أنشر إصدارًا تجريبيًا ولم أنفذ المرحلة الثانية.
